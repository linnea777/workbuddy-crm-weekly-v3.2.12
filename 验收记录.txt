# CRM周报项目包3.2.12

本版在3.2.11上优化，以用户认可的《CRM周报_2026-07-06_2026-07-12_3.2.9.xlsx》洞察作为写作质量参照。重点是让分析自然接到商业地产CRM团队可以执行或讨论的下一步，并减少宿主模型处理格式和接口的工作。

## 本次改动

| 改动 | 业务效果 |
|---|---|
| 分别填写分析段和行动段，程序原样换段展示 | 两段仍在同一个洞察单元格内，不再出现内部有VIC建议、Excel却没有的情况 |
| 拦截行动段缺失、正文与内部建议不一致、合作条件未展示 | 检查实际交付完整性，不只检查JSON结构和数字 |
| 区分日常服务、条件性合作、核查、观察、正式营销刺激 | 原因未完全明确时仍能提出合理的核查与合作方向；低置信不能直接建议营销刺激 |
| 提供主题索引、按主题读取的完整事实和写作草稿模板 | 模型不必从头复制身份、异常成员和结论归属字段，也不需要临时编写结果组装脚本 |
| 规范化数字空格、全半角及等价单位 | 自然中文写法可通过；错误数值、方向及百分比／百分点仍被拦截 |
| 保留每轮调查计时与每次阶段历史，补充指标计算分段计时 | 第一轮耗时不再被第二轮覆盖，后续能分清读取、清洗、计算和输出耗时 |

新版仍保留四个完整few-shot，已同步它们与新写作入口的关系。主体业务规则继续要求：VIC面向星钻卡及已有或确认名单内的高潜黑钻卡；门店合作结合客流、上新与品牌活动；不因销售下降或犹豫未买直接给积分；不以消费人数代替客流或凭空计算到店转化。

- 全场、北区、Burberry、Chanel Beauty四条建议保持原文。

这份样例是认可内容的回放验收与小幅完善，不是另一个宿主模型从零生成的结果。原始运行与用户参考文件均未覆盖。

## 使用

完整导入新版包中`.codebuddy/skills`的六个技能，并同步更新Agent的`SystemPrompt.md`，不要只替换few-shot。常规流程仍为准备、调查、宿主模型写作、导出。

调查后模型先读取`writing_context.json`，按主题读取事实，再填写`writing_draft_template.json`的副本，最后使用`finalize --draft`。已有同一运行的指标和证据时，`--phase writing`可重新生成写作入口，不必重新取数和计算。命令与字段见包内技能入口和`action-delivery.md`。

旧InsightBundle不能直接声称兼容新验收：需要补齐行动段、行动类型，以及条件性合作或观察所需的触发条件。新入口会帮助生成这些字段；必要合并主题仍需正确声明支持范围。

本次未在WorkBuddy内替换已安装技能或从头启动新的模型生成，未重新计算整批原始业务数据，也未测得端到端提速百分比。程序校验能防止内容遗漏与格式错误，建议是否符合当周商业判断仍需按本版写作标准审阅。
