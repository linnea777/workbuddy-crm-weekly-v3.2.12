# 写作与行动交付

质量参照为用户认可的2026-07-06周报3.2.9洞察：先解释本周最值得关注的变化，再自然写明由谁与哪家门店沟通、满足什么条件时讨论何种合作，以及后续观察什么。沿用四个few-shot的判断方式，不增加完整示例数量，也不复制参考周的数字或活动背景。没有必要把每一段写成同一句式。

## 写作入口

调查后先读writing_context.json索引，再读取当前主题的writing/case_*.json。事实采用fact_columns及fact_rows表式表达：同一行按列名解释，包含全部正式事实、范围、期间、适用限制及可用性；不按位置猜含义。无需同时读取完整insight_synthesis_context或EvidenceLedger。每条论断只引用实际支撑它的事实，不把一个case的全部fact_ids复制进结果。

复制writing_draft_template.json为自己填写的草稿，例如weekly_draft.json。程序生成身份信息，模型填写title、analysis_text、action_text及判断字段。保留周、输入签名、实现版本和知识库版本，不能混用不同运行的草稿。finalize --draft会生成正式InsightBundle，自动复制计划身份、异常成员、结论归属和固定结构，不需要临时写Python组装脚本。需要合并多个case时，仍显式填写supporting_case_ids、合法nodes/edges和相应事实，不自动猜测树关系。

analysis_text只写本主题分析，action_text写可直接交付的完整行动自然段。程序只按原文用空行连接，不生成句式、不压缩建议。action_text直接成为内部recommendation.action，避免维护两份不一致的建议。全文仍显示在Excel同一“洞察”单元格，保持主题／洞察两列。

## 行动判断

每条选择主要action_kind，行动段可以自然衔接相关核查，不必拆成多个标签。字段仅供程序，不展示给业务。

| action_kind | 场景及证据边界 |
|---|---|
| SERVICE | 星钻卡与名单内高潜黑钻卡的现有VIC服务。依据当周结构选择跟进重点，不认定所有黑钻卡或大额消费者都属于VIC，不将增长归因于服务效果。 |
| CONDITIONAL | 尚缺客流、上新或活动安排时，提出条件性合作。action_condition写明确触发条件并原样包含在行动段，例如“若门店确认客流偏少且有合适的新品展示”。这只是待讨论方案，不是假定活动已批准。 |
| VERIFY | 明确门店、需要核实的问题，以及不同反馈如何改变后续决定。缺少Mall时可分支讨论经营回落与积分记录变化。 |
| MONITOR | 小样本或高基期等情形下暂不安排营销。说明原因、观察指标，并用action_condition写明复查条件且包含在行动段。重要问题不因暂不营销而省略。 |
| CAMPAIGN | 提出正式营销刺激，仍须有已定位主因与有效证据，不能LOW，存在严重数据质量问题时不得提出。积分支持结合具体品牌安排，不因销售回落、犹豫未买直接加积分。 |

recommendation.applicable=true时填写target、channel、timing、fact_ids，不重复填写action，由程序从action_text生成。所有可执行建议均须引用本主题已选择的正式事实。推荐渠道仍为会员体验活动、品牌联合活动、会员触达、VIC邀约、线下核查或积分活动。已有积分活动的复盘和待核实合作可选择VERIFY或CONDITIONAL，不能借这些类型直接建议无条件发券或加倍积分。

applicable=false时填写not_applicable_reason，并在action_text中写出核查或暂不营销的具体决定，不能留空。LOW仍需follow_up_items；原因未分清可以写核查、观察或有条件合作，不等于必须沉默。严重数据质量问题下优先核查受影响资料，不直接执行营销或按不可靠数据挑选服务对象。

verification_metrics选择与本主题相关的观察指标即可，不逐条列完整清单。门店客流和转化需要门店提供，消费人数及笔数不等于到店客流。相关服务和活动规则见marketing-operations.md。

## 完成标准

提交前逐条核对：行动回应了本主题发现；对象符合分工；合作前提未被当成事实；读者知道下一步以及随后看什么。VIC可在全场集中体现，不在品牌段重复。只做资料核查的主题，应尽可能说明核实后如何决定，而不是泛泛地“持续关注”。

程序检查行动段非空、出现在正文末段、与内部建议一致，以及条件实际可见。数值／范围／引用校验保留。程序检查不代替商业判断，不能仅因PASS就声称建议质量达标。

已获授权生成周报时，任务内的格式修复和finalize应继续完成，不再次询问是否继续。只修出错主题或字段；不重跑未变化的数据和调查。出现相同错误连续两次，读取具体错误和本契约定位原因，不盲目反复运行。缺少必需输入或涉及另行授权的外部动作时，明确说明阻碍。
